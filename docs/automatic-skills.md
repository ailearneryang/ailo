# 自动技能加载（0.1.112）

普通持久对话、任务和定时任务向现有意图判断提供已启用技能的名称、用途与 ID。模型根据当前用户请求选择相关技能；系统内置、用户导入与 SkillHub 安装来源采用相同规则。自动选择不是固定关键词规则，也不是把全部技能正文常驻到每次请求。

## 使用与执行顺序

1. 「扩展 → 技能」设置调用方式：自动可用、仅手动、停用。旧的已启用技能默认自动可用；停用技能不进入目录。专家继续明确选择。
2. `/` 或「＋ → 技能」可以指定本轮技能，优先保留。当前界面会在发送后清空本轮技能选择，后续新输入按其自己的选择与自动匹配处理。
3. 原有 `route` 可携带 `skillIds`，复用同一次意图请求。没有相关技能时仍可以一次 `reply` 直接回答。路由选择后先加载成功，再用下一次请求生成正文或操作，不能在只看到目录时声称已使用完整技能。
4. 执行中发现新的需求时，模型可以调用当前阶段允许的 `load_skill(id, purpose)`。目录只包含可自动加载且尚未加载的技能；已选技能加手动技能沿用最多五个技能、一个专家及 50000 字符原始指令的限制。
5. 成功加载后，活动区显示「自动加载技能 · 名称」，最后的折叠详情保留加载来源。损坏或缺失的技能包不计为已加载，也不阻断其他可用技能。

技能包继续验证保存的文件大小、哈希、目录归属与符号链接边界；引用文件按需读取，较大正文保留原有分页读取机制。加载仅准备指令与资源，不执行脚本、不授予外部操作权限，也不改变原任务的验收要求。

自动分段恢复已选技能及其资源，保留已安装依赖；单次执行中新增技能不会删除先前挂载的技能。进入下一运行段时按完整选择清理已取消的包。失败技能在同一输入内不反复重试，新的用户输入允许重新加载已修复资源。原有副作用账本和失败预算保持独立，加载技能不算任务进展或验收证据。

## 适用范围

临时对话按原有产品约束不使用扩展、记忆与执行工具。纯文本「重新生成」路径继续采用明确选择的文本上下文，本次未将它变成 Agent 执行或资源挂载流程。自动选择依赖当前模型对描述的理解；应为自定义技能写清适用任务和边界，需要确定使用某项时可通过 `/` 指定。

## 验证

固定场景 `automatic-skill-discovery` 关联协议、运行时、真实 chat 服务和配置测试；`skill-runtime-reuse` 覆盖增量挂载和依赖保留。测试使用确定性模拟模型、隔离存储和真实 ZIP 导入，验证普通问候单请求、内置与安装技能选择、手动优先、动态加载、分段恢复、用户插入新任务、损坏资源及修复后重试。Electron smoke 使用本地模拟端点与隔离 userData 验证设置、实时反馈与折叠历史。

这些检查证明加载链路与边界行为；真实语义命中率仍须在同一公司模型、输入和验收口径下另做对照，不能由离线测试推断。
