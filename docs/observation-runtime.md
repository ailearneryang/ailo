本次改造保留 Chat Completions、多模型配置、项目隔离与现有动作协议。没有加入 Sketch 解析器，也没有自动切换模型。参考公开的 OpenAI 工具输入/输出循环与轨迹评测方法；不声称复现 ChatGPT 内部实现。

## 观察工具

`view_image` 读取项目内的图片，支持整数像素 `crop:{x,y,width,height}`。原文件不超过20 MB，解码后不超过4000万像素，输入最长边缩放至1600。PNG 图片通过独立多模态消息进入下一轮决策，不将 base64 写入执行日志。每轮最多发送最近两条尚未送达的图像观察；指定 reference 时每条包含原稿与结果两张图。普通状态决策不反复发送旧图；主动 view_image/browser 可再次回看。保留最多64份图像观察元数据，完整执行记录保留文件路径、哈希、版本和事件 ID，不存图像 base64。发送失败在 visualDeliveryErrors 中明确提供原因，不授予送达或验收资格。

`browser` 支持 `open/inspect/click/fill/scroll/close`。open 的 path 为项目 HTML 相对路径，视口默认1280×900；点击与填写使用 CSS selector，滚动使用 x/y。每次观察包含截图、页面文字、控件概览、页面/视口尺寸、缺失图片、四向越界线索、裁剪线索与控制台错误。统计是诊断线索，不是自动视觉结论；页面异步更新时需再次 inspect。单次操作最长20秒。

网页运行在独立的非持久 Electron session、sandbox renderer 中，没有 Node、个人浏览器登录态或系统凭据。仅服务项目内受支持的资源，拒绝符号链接、隐藏文件、外部地址、非 GET/HEAD 请求、下载和额外窗口；限制页面权限、frame、表单和网络请求。不支持后端服务或依赖远程资源的完整网页运行。现有静态侧栏预览继续使用原实现。

观察记录实际读取资源（含缺失资源）的哈希，CSS/JS/HTML 等依赖被修改后必须重新打开。无关命令、翻页和后续点击不会抹除已有历史观察；交互前后、不同页的快照可同时作证，rendererState 标记各自观察时的状态版本。运行结束、停止或退出应用会关闭观察窗口。截图保存在项目 `.ailo-observations`，可按需登记为成果。

## 模型能力

模型设置增加 imageInput：auto（默认、尝试发送但未预先验证）、enabled（用户确认支持）、disabled（不发送图像）。图像发给当前模型服务商，不自动改用其他模型。端点明确拒绝图像时保留进度，按文末能力边界转为文本检查；不将视觉项记为通过。请求接受图片仅证明传输成功，不能证明模型理解或判断准确。

## 验收与完成

### 通用生成与修复闭环

生成指导按“源结构→小范围验证→生成→实际运行或渲染→对照要求验收”组织。运行时不预设失败原因，也不强制所有格式使用相同的检查。格式说明由 `agent/format-guidance.cjs` 根据附件扩展名按需提供；目前只迁出了已有 Sketch 指导，没有新增完整 Sketch 解析器。

`verify` 失败时，`agent/validation-recovery.cjs` 将实际失败的要求、检查方式、对象、错误和归档凭据保存到 `run.validationRepairs`，并撤销该要求之前的通过结果。模型下一轮通过 `repairTargets` 看到仍未解决的目标，可用 `read_execution(id=failureObservationId)` 回查完整失败检查；失败记录跨重启保留，每个要求保留最近八次失败摘要，完整凭据仍在归档中。已有页面缺陷继续由页面诊断模块管理，不另加天气页面专用修复流程。

原因假设仍需模型用源数据和实际运行记录确认，确认的事实通过 `progress.executionState.facts` 绑定来源。写入修复文件、更新计划或解释原因均不会关闭目标；只有整个 `verify` 批次通过后，对应目标才标记为已验证。批次中后续检查失败时，前面的检查不会提前关闭目标或获得新的验收资格。若失败来自不符合原要求的检查本身，可以纠正检查后重新验证，不要求无意义地修改正确成果。

系统管理的问题可通过 `progress.issues` 仅提交 `id/status/evidenceId/reason` 更新。运行时始终保留检测器的原说明、原范围和要求关联；模型重述的 description 仅保存为历史备注。新建普通问题仍须提供 description 与 requirementIds。关闭系统问题仍核验最新、覆盖原对象的页面证据，省略字段或重述说明不会绕过检查。

这些机制保证失败目标不会因错误预览消失或旧验收结果而被掩盖，不保证模型一定能找出原因，也不构成自动视觉质量证明。缺失能力时仍须保留进度并如实报告阻塞。

plan 可提供与 acceptance 一一对应的 acceptanceTypes：presence/content/behavior/visual。未提供时按 content 处理。plan 可直接提供 requirements:[{id,text,type,scope/scopes}]，acceptance 和 acceptanceTypes 由运行时生成兼容镜像，无需重复填写。旧记录沿用原哈希 ID；新记录保存独立要求身份。同一输入下要求不能省略、换 ID 或更改验证类型；改写措辞保留原 ID 并使原检查待复核，不能借改写重新开始验收。

verify 保留 command/file_exists/text_contains/json_valid，增加 visual/observation：

- presence 可用文件存在检查；文件存在不能证明内容正确。
- behavior 要求命令或运行观察证据。
- visual 必须使用已传入模型的当前版本图像事件，不能用关键词替代。
- observation 绑定真实网页观察；网页存在缺图或控制台错误时须先修复。

结果记录依据类型：machine_check 或 model_assessment。图像与页面语义判断属于模型评估；UI 不把它显示为机器证明。批量检查原子提交。同一要求可关联多份证据（例如交互前后或两个文档区域）；声明多个 scopes 时必须全部覆盖。证据依赖文件变化后重新验证，局部证据不能扩大为整页证明。

finish 仍要求任务计划、登记成果和适当证据，但浏览器/图片观察可替代无关的 shell 命令。必须提供 review:{summary,issues,unverified}。问题通过 progress.issues 按稳定 ID 增量更新，空列表或省略不会删除。resolved 必须关联覆盖原对象/范围的有效修复证据；limitation 必须说明为何不影响要求。浏览器发现的缺图和运行错误会进入持续记录，四向越界仅作线索。finish.outcome 为 complete/limited；limited 仍需全部要求已核验，在 review.issues 引用 limitation ID，交付文字披露问题说明。未满足核心用途时须继续修复或 pause/blocked，保存 partial/blocked 交付状态。运行时检查关系，模型判断语义，不将主观质量包装成机器证明。有效格式的复核在运行记录中留存，成功交付可在进度详情查看。

收尾阶段允许继续针对性读取与修复。保留重复动作检测、失败恢复、预算和权限机制。上下文近期工具结果由3条扩大到6条；短文件缓存从4份/8000字符扩大到6份/12000字符，同时提供近期错误记录和原始归档回查。并未改成无界发送全部历史。

运行时不能自动证明模型选出的验收要求已经覆盖全部用户语义，也不能防止错误的主观判断。这些仍需通过跨任务评测与抽样人工检查评估。

## 精确目标与文本范围

browser.open/inspect 的 selector 选择实际完整可见元素，crop 选择当前视口整数 CSS 坐标区域，两者互斥。click/fill 的 selector 仅指定交互对象，默认仍截图整个视口，避免把按钮局部截图当整页。结果 scope 包含实际项目路径、元素选择器或页面坐标矩形；pixelSize 记录截图物理像素，处理 Retina 比例，回看裁剪区域正确映射到 CSS 坐标。

dom.visibleText 是视口内可见文字的几何近似，过滤隐藏/透明及完全裁剪文字；不能证明无遮挡、对比度或视觉质量。dom.fullText 是 DOM 文本（可能含隐藏内容），另有截断/诊断覆盖标记。两者不可混用。截图仍是视觉判断依据。

目前直接适配 HTML 页面与栅格图片；PDF/Word/表格等可先通过相应渲染工具产生页面图片，但没有凭一张 PNG 自动证明它对应某个原文档页面的专用适配器。文档可用各页实际图像路径作为范围；PNG 若来自已记录命令且内容哈希相符，会继承该命令完整记录的项目依赖，源文档变化后要求重新渲染。不能凭模型填一个页码就证明 PNG 对应原文档某一页，这种语义映射仍需格式适配器或模型结合实际结果核对。

## 兼容与回滚

保留 acceptance/acceptanceTypes、粗粒度 run.status 和旧 check 记录；缺少依赖哈希的旧证据继续保守使用 revision 判断。新增要求、问题、delivery、executionState 等字段与旧执行账本并存，新终结轮次单独归档，不改写已结束轮次。回滚源码可使用本轮 baseline 快照及 manifest；先停止使用新运行时的活动任务并备份数据，旧运行时不理解新问题账本与复合证据，不能据旧版展示判断这些新任务已经验收。无需迁移或清空原用户数据。

真实模型首轮试验暴露了过严的交互状态失效与单要求只能有一个证据的问题；诊断轮次分别保存在 candidate-attempt1/candidate-attempt2/candidate-attempt3，修正后另冻结候选版重跑，不将诊断轮次混入最终30次候选样本。

finish 的 evidence 字段改为可选操作引用；实际完成资格始终由已通过且未过期的 acceptanceResults、问题账本和成果哈希决定。已知的写入/登记引用不能授予验证资格，虚构记录仍被拒绝。delivery.proofs 自动保存每条要求真正采用的检查，避免模型在交付时重复抄写 UUID。

## HTML 交付与修复回归补充

- 页面交付至少需要一次当前文件的完整视口观察及已送达模型的截图。元素/区域截图可用于细节检查，但不能单独替代页面级观察；即使截图指定 selector，布局统计也扫描文档，并报告扫描截断。
- 裁剪按各轴的 overflow 判断。可通过 auto/scroll 容器实际滚动范围访问的文字单独计入 scrollableTextNodes；固定裁剪或负方向不可达内容计入 clippedTextNodes。隐藏及 aria-hidden 内容不作为主体裁剪比例的分母。长文档不因超出视口自动失败。
- 当前文件的新观察若包含严重裁剪或运行错误，不能回退采用较早健康 UI 状态的截图。文件和依赖哈希保持有效时可以复用页面观察，无关文件改动不强制重看。
- HTML 交付检查被拦截时，运行时保存稳定的问题 ID、证据与修复目标，重新打开最后一个已完成步骤。新的页面级观察通过后关闭对应运行时问题；普通语义质量仍由模型依据要求判断，几何通过不代表视觉完美。
- 原文、执行日志等读取动作补齐进度文案；空值或状态展示回调异常不再阻断工具。生命周期测试使用真实临时文件和确定性检查替身，命令隔离、退出码及真实 Electron 渲染仍分别做集成验证。

### 重复动作的内部恢复

同一非读取动作达到重复阈值，或同一读取范围在纠正提示后继续重复时，运行时阻止再次执行并进入 `loopRecovery`，不再以 `no_progress` 直接暂停任务。模型收到精确动作位置、对应归档凭据和近期观察证据，自动聚焦当前缺口并选择修复、不同范围的读取、有效证据核验或交付。整批只有计划/摘要等记账操作而没有有效进展时也进入内部恢复。恢复期间不能用 `pause/blocked` 把重复动作问题交回用户；真实权限请求和 `clarify` 仍按原流程等待用户，用户主动停止仍立即生效。成功的不同实际操作或核验可退出循环恢复，重复动作计数不会因为换一批执行而清零。原有总轮数和时长预算仍保留，避免模型始终不改变决策时无限消耗；未完成任务不会伪装为成功。

### 自动收尾与视觉能力边界

`visualReview` 表示当前可以尝试视觉评估，而不是理解准确性的认证。`imageInput=auto` 且有图像服务时，`images/visualReview=true`，`imageUnderstanding=unconfirmed`；用户显式启用时为 `user_confirmed`。不能仅因 auto 未预先认证就自动放弃视觉要求。禁用图片、没有图像服务或端点明确拒绝图片时，才进入能力受限路径。

当前输入对应的计划已完成、登记产物哈希未变、全部非视觉要求已有新鲜验收证据，并且没有未解决的实际缺陷时，若只剩无法执行的视觉要求，运行时可生成带限制的 `finish`。视觉要求保持 pending，`delivery.visualReviewPending=true`，正文列出未核验项。已知设计差异、缺少非视觉检查、产物改变或计划未完成时不能走此路径。端点明确拒绝图像输入后，同一任务自动改用纯文本请求继续，不重放已执行工具。

### 成对观察与提前返工

`view_image` 支持 `reference` 原稿图片相对路径。每次观察发送当前结果与原稿两张图，原稿即使以前已送达也会重新随结果发送。每轮最多两条新观察（两组对照最多四张图），不归档 base64。原稿哈希也作为证据依赖；更改原稿使旧证据失效。

整图对照可运行粗略色块检测，大面积差异立即撤销视觉验收并重新打开已完成步骤，不等到 finish。`visualComparisons` 保存最多12个对象的最近完整对照，恢复上下文保留差异；裁剪、无关对照和重复截图不能消除已知缺陷。新整图对照排除粗略差异只允许继续语义核验，不自动通过验收。其余组件缺失、文字和局部间距仍需模型或人工判断。

Android 对照使用 `android-design.json` 中的 reference 与真实设备截图；绑定画板、layout、原稿、APK和截图哈希。成对观察的完整范围为 `viewport` + layout 路径；交付使用最近有效的成对截图，无需反复修改配置中的旧截图路径。错误的旧 scope（例如把整个 Sketch 文件当成运行页面）不自动放宽，须明确澄清修正。新计划尚不能确定范围时可省略 scope，但保留完整验收语义。

`verify kind=observation` 支持 Android 安装、启动、日志和截图事件，要求真实成功结果及未变化的安装 APK。启动失败、崩溃日志与过期 APK 不能作通过证据。安装或截图只证明对应操作，不能代替搜索、点击、选城等交互测试；本轮未扩展模拟器操作权限。

`android_device operation=check` 可组合现有的准备、安装、启动、日志与截图操作，逐步保留真实事件和副作用账本，不扩大权限、不执行点击。已成功归档的步骤可复用；结果未知的安装/启动不会重放。标准构建也返回 APK 的 scopes 与输入/产物哈希，后续可直接使用对应 command 证据，无须额外生成“构建成功”文本。

短工具读取在恢复上下文中保留全文，更新记忆不再清空近期观察；独立 checkpoint 保留最近两条。进度面板将步骤数量、有效验收数量和视觉验收数量分开展示，新增耗时分解和运行时错误统计。详细策略与有界诊断保留见 [Agent 效率改造](./agent-efficiency.md)。

### 长任务的证据归档与附带记账

`run.events` 只保留最近100条记录，证据有效性不能由它决定。证据查找现会按任务回查 `.jsonl` 归档，并继续检查事件类型、依赖哈希、截图来源及最新页面缺陷；唯一的 ID 前缀和 observationId 可解析为真实事件，虚构引用及跨任务引用仍被拒绝。收尾可复用归档的最新页面观察，不能用旧的正常页面掩盖更新后的错误。带限制交付接受“验收项 ID：说明”并规范化为原 ID，不允许通过相似前缀跳过其他要求。附带 executionState 中没有有效来源的声明保留为未确认内容，不计为已确认事实，也不阻止原动作；步骤、权限、成果及验收本身的校验仍保持独立有效。
# Android 设计逐区域验收（2026-10-23）

绑定画板后，`androidDesign.screens[].baseline.designManifest` 由原稿生成区域 ID、边界、文字/图片数量及重复组。重复组按同父级、同尺寸容器或图形识别；组件实例与拆散后的 group 可归入同组，重叠合成图层不计为并排控件。数量、行列和位置来自当前原稿，不依赖“天气”“六张卡片”等任务名称。它是结构核对依据，不是完整的语义识别器。

原稿 `color` 和 `palette` 保留 RGBA 以兼容读取；新增 `androidColor` 明确输出 ARGB。嵌套组件的文字尺寸按实例缩放展开；上下文提供画板像素到目标 dp 的比例，生成时仍须处理系统栏、sp 字体缩放、字体替代和默认留白。加载、空数据及错误状态不得删除应有区域，缺少数据不得借用其他字段冒充。

受授权的项目模拟器截图会附带一次有界控件树采集：固定 SDK 命令、项目专用设备、随机临时路径、最多 2 MB、最多5000项、禁用 DTD/实体。只列出当前应用节点，完整 XML 在 verification 目录，哈希并入截图来源；采集失败明确返回 unavailable，不重装或重启应用。截图与控件树是相邻采样，不能证明其间没有状态变化，自绘内容可能不在控件树中。

Android 成对视觉观察返回 `designManifest` 和 `uiHierarchy`。`verify.checks[].regions` 须覆盖清单，每项填写 id、status（matched/mismatch/unverified）、实际观察 reason 和 repeats；重复组含 id、observedCount、rows、columns、basis（image/hierarchy）。图像依据仍是模型评估，须说明可见项目，不能照抄预期数量；控件依据引用真实 nodeIds，运行时核对数量、行列、位置、相近尺寸及是否超出屏幕。位置比较按画板与截图归一化：中心偏差容忍2.5%视口或组件15%中的较大值，尺寸比为0.65–1.5。这只是明显结构错误的辅助检查，不证明像素一致。

`mismatch/unverified` 记录为持久化区域缺口，使视觉验收失效，并在进度面板显示具体原因。摘要、重启、重复截图和低色差不能清除；同一结果图不能直接改称修复成功。完整的新区域证据通过且整批验收成功后才关闭缺口；来源改变继续使旧证据失效。旧的 Android 色块式通过记录需重新成对观察及逐区验收，纯构建任务不增加视觉要求。缺少图像能力不能豁免已知区域缺陷。

`comparison.visualAcceptance` 始终是 unverified，`changedFraction` 仅为64×36采样色块中超过阈值的比例，不是设计差异率、还原度或通过率。全图颜色相近不能替代组件、排列、控件语义、文字和资源的检查。模型的逐区图像评估仍可能出错，最终质量需要真实任务和独立复核；离线回归不提供真实还原率。
