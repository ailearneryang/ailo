# Ailo 回归与交付质量

0.1.65 的长任务改造、固定新增故障与真实对照入口见 [长任务优化](agent-optimization-20261025.md)。当前工程回归与宿主／真实模型验证分开报告。

修复的目标是减少同类故障再发，并提高完整正确交付的比例。单元测试通过、模型返回动作、构建成功、状态显示完成，分别提供不同证据，不能相互代替。

## 固定故障回归

`scripts/reliability-cases.cjs` 保存历史故障与测试文件的对应关系。新增修复应补充原场景和一个相邻变体，保留已有场景；变更恢复策略时，测试继续核验实际副作用、证据和最终状态，不依赖过时的暂停次数。

```sh
npm run test:reliability
npm run test:reliability:host
```

第一项验证公司网关兼容、无动作恢复、事件回查、源码复用、续跑、大文件、证据和设计完整性。第二项还验证宿主命令与构建沙箱，需要可以正常运行 macOS `sandbox-exec` 的环境。外层沙箱干扰时需在合适环境重跑，不能把未执行或跳过算作通过。测试使用隔离文件与确定性替身，不调用公司模型、不改用户任务、不启动真实模拟器。

每次结果保存在 `.local/quality/reliability-latest.json` 和 `.tap`；历史 JSON 与诊断保存在 `.local/quality/history/`。报告记录测试集合、源码指纹、失败、跳过和取消数量。无测试、跳过、未完成、非零退出或测试期间源码发生变化，都不能得到通过报告。

`schedule-history-evidence` 保留定时历史 `execution.json` 因上下文加载被重写、命令证据随之失效的场景。已归档完整结果由归档操作更新，上下文加载不再用精简投影覆盖；缺失的旧记录首次迁移并记录来源哈希，真实来源变化时仍更新迁移快照。索引仅在实际记录变化时更新时间，时钟推进或重复加载不改变证据依赖字节。全部历史路径继续参与原有哈希、文件集合及验收检查，不排除整个 schedule-history 目录，不改旧回执哈希来伪造新鲜度。真实依赖变化仍撤销旧通过记录，并在恢复目标中标明变化路径及状态；读旧输出不刷新证据，必须重新获取受影响的真实检查，结果未知的副作用不重放。固定场景覆盖跨上下文续跑、完整归档保留、迁移真实更新、损坏记录显式失败及真实成果变动后的重新核验。

`runtime-continuity` 保留 `net::ERR_NETWORK_IO_SUSPENDED` 被误归类为业务诊断缺口及网络恢复后继续被拦截的故障。允许列表内的网络异常在请求边界统一分类，沿用每次请求最多两次自动重试；流中断的残缺工具动作不执行，可见输出与用户取消仍禁止自动重放。旧任务的原始网络错误可识别为等待网络恢复，用户点击“重试当前步骤”可沿原任务进行新的有限请求，不要求填写业务诊断或固定口令，不在后台无限重启任务。授权、证书、预算耗尽、用户暂停及结果未知的操作不适用此入口。固定用例验证五项要求、五项步骤、零登记成果时工作文件仍保留、原写入不重放、请求标识诊断可追溯；网络错误不能证明具体休眠原因，也不能证明成果已经完成。

`pagination-compat` 保留只读 `limit` 导致连续协议失败的场景。运行时仅对 `read_file`、`read_material`、`read_history`、`read_execution` 的单页长度做有界适配：安全正整数超限时缩至 12000（本地批量为 4000），可选空值按省略处理；对象与 offset 不变，后续读取遵循模型实际可见结果的 next。零、负数、小数、不安全整数和含糊字符串仍拒绝，offset 与连接器参数不做此类适配。纠正消息记录动作、参数、数值或类型，避免保存任意字符串正文；两次纠正上限、权限、批次整体验证和重复读取预算保持生效。用例验证全文确实被逐页读取、错误批次零执行、证据保留和原任务续跑；不以分页成功代替任务验收，也不据此声称公司模型真实任务完成率提高。

`checkpoint-contract` 保留短摘要反复报工具失败及恢复提示与执行校验不一致的场景。具名工具、常规与恢复提示、独立摘要和附带记忆统一采用20–10000字符约束；去除首尾空白后不足20字符仍拒绝，不自动补字、截断或编造来源。缺少 checkpoint.text 时仅复用同一动作显式提供且合格的 progress.memory，明确无效的 text 不被覆盖。摘要格式在任务状态变更或工具执行前校验，按协议最多纠正两次，反馈字段、类型与长度而不保存摘要正文到错误诊断。用例验证无效动作不改步骤、记忆或检查点计数，纠正后按原验收交付，原始归档可回查、原任务可续跑；摘要记账不会重置无动作恢复预算。摘要事实是否充分仍需真实任务与验收证据判断。

`verification-request` 保留无效验收 ID 与重复检查被混报为成果验收失败的场景。工具定义使用当前 acceptanceCriteria.id 作为可选值，运行时在状态变更与验收前校验整批身份，纠正反馈指出条目位置、重复位置或可用 ID，不按序号或语义猜测映射，也不静默删检查。错误请求不撤销旧通过记录、不生成成果修复目标，不计为实际验收失败；旧记录仍须通过内容哈希、新鲜度与范围检查才能交付。相同要求的不同证据或范围继续允许，同一证据的重复记录拒绝并要求合并；纠正后按原验证类型、内容与范围执行真实检查。固定用例同时覆盖整批原子性、三种响应模式、有限纠正、原任务续跑与稳定 ID，不能据此声称真实成果质量提高。

该场景同时保留“请说明检查如何覆盖这条验收要求”的重复故障。checks 的工具定义与请求校验共享参数约束：reason 为1–800字符非空说明，缺失、类型错误、空白或超长时反馈条目、类型及长度，诊断不保存说明正文；kind、文件检查的 path/contains、证据检查的 evidenceId 等核心字段一并在整批执行前校验。不得自动补写说明、截断证据、修改成果迎合参数或把格式错误记为成果修复。真实内容缺失、证据过期、验证类型不符与范围不足继续由原验收机制拒绝。

`feishu-request-contract` 保留“飞书操作无效”导致同一问题恢复耗尽的故障。具名工具、合并菜单和 JSON 合同仅允许 schema/api/help/shortcut，并按操作要求 query 或 method/path；执行边界与协议校验共用纯参数构造器。无效操作、方法及参数在状态更新或执行前拒绝，按原有两次协议纠正反馈具体规则，不计入业务修复预算，不把 search/read 猜测映射为写操作。恢复分页测试经过真实参数校验，不再接受虚构的 search 操作。隔离用例覆盖纠正后真实桥接路径读取、连续无效动作零调用、显式续跑保留原任务和文件；原有未知写结果防重放与重复读取失败预算场景保持运行。旧版已知本地“飞书操作无效”阻塞允许用户触发一次修复后续跑，桌面入口与后端使用同一判定；消费标记持久化，不因空模板、摘要或重复点击重置。三项要求、五项步骤的旧任务沿同一执行ID核验原文件，无结果未知操作时才适用；授权、超时及其他缺口仍须实际解决。不调用真实飞书或用户模型，离线通过不代表真实任务完成率提升。

`scheduled-message-delivery` 保留晚间复盘提醒被当作文件任务、reply 连续拒绝及观察验收失败的场景。定时只是触发方式，明确面向用户的纯文字提醒及只读来源总结按 chat/reply 交付；“向用户发送提醒”和公告参考链接不自动解释为外部发送，消息总结仍先读取真实来源，不凭历史编造本期结果。普通文件、应用执行和外部发送要求仍走原有路由与验收。历史上下文只作数据，不再向所有任务注入课程地图或创刊流程；当前要求涉及回顾、连续进度或去重时仍读取相应真实历史。旧误分类提醒可沿同一执行ID恢复；保留旧步骤、要求、文件和未通过记录，不伪造验收通过，不把邀请归档当作实际归档。结果未知、服务授权或无关业务故障不能因此获得盲重试。隔离用例覆盖新一期单次消息交付、旧阻塞和澄清状态、定时运行完成记账及混合文件／外部任务不被降级；不调用真实用户模型或修改实际定时任务。

`dictation-privacy` 保留麦克风点击后听写子进程因缺少 NSSpeechRecognitionUsageDescription 被 TCC/SIGABRT 终止、而父进程将 signal 退出误报正常 end 的故障。主应用与独立 Swift 子程序都声明麦克风和语音识别用途；子程序通过 Mach-O __TEXT/__info_plist 嵌入声明。编译后与最终包均执行不申请权限、不录音的 --check 自检，缺失声明或复制了旧二进制时阻止打包。原生源文件、plist 和构建脚本进入回归指纹。SIGABRT 等异常退出必须反馈明确错误，已有原生权限错误不能被 exit 事件覆盖，取消不会提交残余文字。宿主场景编译隔离二进制验证实际 Bundle.main 可读声明，不触发真实麦克风和系统授权；另保留报告中 parentProc=Ailo、responsibleProc=Code 的真实故障：macOS 启动通过 open/Launch Services 打开精确版本的 .app，避免直接 spawn 继承编辑器权限责任链；-n 保留单实例锁检查，私有日志转发保留诊断与重复实例非零结果。隔离无界面探针验证真实 .app 身份与非Node父进程，不读取麦克风、不修改VSCode权限或系统TCC数据库。另保留完整Electron包残留资源签名导致 open -10810 的故障。标准打包末尾对本地产物重新作 ad-hoc 签名并严格验证资源封印，保留原有entitlements与runtime flags，不修改Gatekeeper或系统信任设置。最终包必须通过真实Launch Services启动自检；自检在锁、存储、模型、定时器和窗口初始化之前退出，使用隔离userData目录，核对真实版本及app.asar路径。签名变化只允许签名元数据不同；听写程序用去签名后的完整字节比较，正文变化仍拒绝。启动命令显式清空 ELECTRON_RUN_AS_NODE，避免从编辑器环境继承 Node 模式后拒绝应用参数；最终包自检与实际启动共用命令构造器。另固定同一0.1.85包仅日志位置不同即可复现的-10810：Launch Services启动前打开Documents下stdout/stderr被拒，而系统临时目录可启动。正常启动与最终包自检共用createLaunchLogs，使用系统临时目录下0700目录、0600日志，不能回退到项目Documents路径或要求扩大文稿访问权限；日志转发和重复实例错误仍保留。真实权限授予及录音效果仍须用户设备确认。

## 打包前后检查

`versioned-desktop-start` 保留 Forge 按 `buildIdentifier` 输出到 `out/<版本>/`、而 `npm start` 仍读取旧 `out/Ailo-<平台>-<架构>/` 的故障。启动器使用与 Forge 相同的目录标识，并在执行前校验 ASAR 的 package.json 及 macOS 两个应用版本字段与源码一致；当前包缺失、损坏或不一致时明确失败，不回退旧目录，也不以修改构建目录伪装升级。启动器本身加入回归源码指纹。已有实例占用单实例锁时，新进程明确提示本次未切换版本并退出，不在后台重复初始化任务或存储；不会自动终止用户任务。

`auto-model-routing` 固定场景覆盖 Auto 的主模型、视觉模型与各自一个备用模型。仅在用户选择 Auto 且开启备用切换时，暂时性服务错误在原请求有限重试后使用指定备用模型；同一轮执行不来回探测故障模型，不重新创建任务、重置失败预算或重放工具。手动选择继续绑定原模型。鉴权、明确额度不足、协议和验收错误、证书错误、用户取消、已展示正文和结果未知的副作用不触发自动换模型。请求诊断保存实际 modelId、用户选择与请求类别，回复详情记录切换原因。

视觉模型必须由用户在设置中明确确认图像能力，已知纯文本端点不能因配置变成视觉模型。Auto 只发送相关图片、来源标签和必要任务背景给指定视觉模型，观察结果带模型身份与输入哈希回传主模型；原稿和当前截图同请求送达。视觉调用没有执行工具，观察格式仅允许一次纠正；同一图片与问题可在本轮复用，像素或问题变化后重新分析。完整观察保留于执行记录，当前上下文采用可回查的有界预览。图像送达、视觉模型意见和自动切换均不等于验收通过，真实图片与依赖仍受原有新鲜度、范围及已知差异约束；无可用视觉模型时明确保留缺口。临时或仅回复会话读图片不会创建 Agent 工作区。离线用例只使用替身端点及隔离图片，不调用用户模型或设备，不能证明真实模型识图质量与成本已提高。

Electron Forge 的 `prePackage` 必须运行固定回归；`postPackage` 检查报告仍对应当前源码和用例，并逐个比对 `app.asar` 内的 Agent 运行时文件与已测试源码。`package`、`make` 及正常启动前的打包都经过同一检查。失败会阻止此次构建成功结束，不发布或删除旧安装包；也不会替换正在运行进程里的模块。

`stable-desktop-install` 同时保留安装路径不变、ASAR 内容布局变化时读取旧缓存偏移，将网址片段当成 package.json 并报 JSON 解析失败的故障。每次读取应用元信息前失效该路径的 ASAR 缓存；隔离用例实际创建两个布局不同的 ASAR，经过完整替换流程验证新版本元信息，原有失败回滚和运行中保护继续执行。

`stable-desktop-install` 将日常安装固定为 `/Applications/Ailo.app`。`npm start` 完成标准打包后再校验回归报告与最终构建，以隐藏暂存目录复制、逐文件哈希核对、严格签名校验、同卷重命名和安装路径启动自检更新应用；随后从固定安装位置启动。构建、复制、验证或自检失败时保留或恢复旧安装，不回退启动旧版本。已运行的同字节应用无需重写，旧版运行中则阻止替换并提示完全退出；复制完成后再次检查运行状态，未知目标和符号链接不覆盖。用户数据目录不复制、不删除，不自动终止任务。版本构建输出仍可回归追溯，成功同步后取消构建副本的应用搜索注册。离线用例覆盖副本损坏、运行竞争、首次安装失败、回滚、无变更复用和用户数据隔离；宿主用临时应用验证真实复制、签名与安装路径启动，不安装到用户应用程序或触发真实任务。

## 真实任务质量

现有跨任务评测使用固定任务、重复次数、原始输入和验收标准。比较两个运行时版本时，保持用户选择的公司模型、服务端点和设置一致；不以更换模型、删除难例或降低验收标准制造提升。真实评测会调用模型服务，需作为单独的明确测试执行，不由打包检查自动发起。

```sh
npm run eval:report -- .local/evals/<对照实验目录>
```

报告分别保留完整交付声明、带限制交付、独立机器检查、人工待验收、确认正确交付、已知错误完成及无动作响应影响的次数。带限制交付和仍有未核验要求的结果不计为完整正确交付；空检查列表不算自动通过。仍有待判定的质量样本时，不输出正确完成率。服务鉴权、额度和明确的服务不可用单独列出；框架暂停、无动作或协议失败保留在有效失败样本中。

离线回归只证明已覆盖的机制场景没有退化。实际完成率、设计还原度和语义质量是否提高，需要完整真实任务、独立功能检查和人工复核提供新数据。恢复后继续成功率仍是单独待测指标，不能用离线续跑测试替代。

## 活动摘要与命令输出

活动行展示当前动作，展开后显示最近操作时间线；命令和输出再按需展开。内部进度与记忆更新保留在独立折叠区，不覆盖当前动作。普通宿主命令和标准 Gradle 构建将真实输出约每秒推送到界面，短命令结束时补发最后一段；阅读旧输出时不强制滚动到底部。命令输出沿用末尾 24,000 字符的保留范围，发生截取时明确标记，不称为完整日志。命令成功、失败、超时或中断后结果待核对分别展示，均不代替任务验收。

固定场景 `activity-log` 覆盖摘要、分层日志、执行中输出、中断保留与禁止重放；宿主集合中的 `command-output-host` 使用隔离临时目录验证真实 stdout/stderr、最后一段、截取标记、UTF-8 分片与 Gradle 输出转发，不操作用户任务或真实模拟器。

折叠活动行依据真实执行阶段保留任务上下文：执行中展示操作及对象，工具返回后展示最近操作与“正在分析结果”，恢复时带上当前任务步骤，明确等待授权或失败时展示已记录的原因。内部记账事件不覆盖这些信息；授权申请返回不等于授权已获批准，下一步计划不等于已经执行。`activity-headline` 保留“模型部署＋长授权说明＋自动恢复＋内部记账”的原故障与相邻变体。

活动区采用“单行摘要＋展开时间线＋单项输出”的布局。摘要截取具体操作的短句，并分别标注执行中、分析结果中、自动重试中、等待授权或受阻；完整操作说明保留在单项详情中。时间线保留真实操作的先后顺序，相邻恢复记录合成一个默认收起的“自动调整执行方式”节点，中间有真实操作时分组断开，不跨操作合并，不将记录条数当作重试次数。上次更新时间仅依据实际操作结果，不由恢复或记账刷新。协议词译为日常用语，原始诊断与输出保留可回看入口。`activity-log` 与 `activity-headline` 同时保留旧故障和截图基线的新变体，覆盖无假进展、诊断不丢失、设备操作语义和分组不吞掉真实操作。

只有与当前活跃会话绑定的 `inFlight` 动作显示旋转指示，折叠摘要和对应时间线节点同步显示。命令结束、暂停、等待用户或授权以及历史快照均不显示旋转；模型分析阶段也不继续为上一项工具操作转动。减少动态效果设置保留静态指示和状态文字，不播放旋转动画。`activity-log` 验证这些状态边界。

时间线在任务面板内保留独立图标缩进，防止通用 ol/li 样式覆盖后遮住标题。截图故障与实际组件布局检查保存在 `.local/verification-ui-qa/`，覆盖宽屏、390像素窄屏放大字体和深色模式；历史错误内容继续可查。

## Auto 配置页

配置页先展示主模型与视觉模型，备用选项位于“服务不可用时自动切换”开关下，关闭后保留原选择。实际模型 ID 与图像能力声明分开展示，用户声明不标为识图验证通过；无视觉候选时提供按模型直达图像输入设置的入口。长说明默认收起，缺少备用时说明相应服务不可用后的保留行为。保存状态区分尚未配置、有未保存更改、已保存与保存失败；未修改时禁用保存，能力编辑不丢弃其他有效 Auto 草稿。隔离浏览器检查覆盖保存失败、关闭重开、能力编辑联动、无视觉候选、宽屏、390像素窄屏放大字体与深色模式；验证记录保存在 `.local/auto-model-settings-qa/`，不修改用户模型或调用真实接口。

## 局部恢复与成果收尾

`result-settlement` 固定场景覆盖视觉观察格式连续无效却被归因为服务授权／用量故障、继续按钮重复旧阻塞、局部恢复耗尽后已有成果不可见。视觉通道在一次定向纠正后将失败作为只读反馈交回执行器；失败不登记为观察证据。同一来源图像的失败在当前执行持久保留，不因重复送图、进度或摘要变化更新预算；实际来源变化、用户明确发起新的续跑输入或运行时／模型配置变化后允许新的有限观察窗口，旧失败记录仍保留。完整 JSON 代码块可做确定性提取，字段校验与视觉验收标准不变，不调用其他服务商规避格式问题。

普通工具恢复耗尽且已有实际工作时进入剩余工作阶段：保留原故障过程，允许继续处理独立要求。相同失败对象在版本未变化时不再执行；真实新增效果与有效检查可以继续，重复读取和记账不刷新空转预算。剩余工作连续 12 轮无实际进展，或本轮已无可行工作时，使用独立的确定性收尾路径整理文件与缺口，不依赖再一次模型调用成功。最终执行批次预算耗尽也可进入此路径；受限诊断评测仍按原预算暂停。未知副作用、用户取消、必要权限与真实服务故障保持原有保护，不以成果收尾掩盖或重放它们。

收尾逐个核对文件非空与当前哈希，同时合并已登记文件、成功写入回执和命令／构建输出回执（包含独立观察归档），不再只在零登记时找回文件。已登记路径发生变化时重新登记当前版本并保留旧哈希，未观察到的外部变化同时推进保守版本失效；旧验收证据不能随登记更新而变新。缺失、空文件或无法匹配真实回执的未登记路径不能冒充成果。每项通过证据重新检查有效性，过期检查保留历史但不计当前通过。未满足要求、原计划、开放问题及原执行 ID 全部保留；`partial` 和 `delivery.status=settled` 表示本轮已交付部分成果，并非原任务完成，不修改步骤或把缺陷转成已接受限制。用户在原任务继续可沿原执行与证据处理，先前成果卡保留在对应回复。无可交付文件时仍明确记录未完成，不形成服务恢复口令。

结果小图标区分完整完成、带限制或待确认、部分成果及未完成。检查通过项数仅表示证据覆盖，不是视觉质量分数；定时记录与质量报告单列部分成果，不计完整正确交付。离线场景使用隔离文件及模型替身，不修改真实任务或调用用户模型，不能证明真实完成率与视觉效果已提升。


## 统一结束策略与有依据的文本交付

`result-settlement` 同时关联 `unified-exit`，固定原先七类缺口：执行器提前受阻、可选工具故障中断全局、混合登记和命令产物漏收、当前文件版本与登记不同、无文件分析结果丢失、交付动作格式失败、未归类内部错误。`exit-policy` 将真实服务故障、必要权限、用户取消及未知外部结果与内部异常分开；内部异常采用默认收尾策略，而不是根据 `MODEL_` 前缀索要“服务已恢复”。普通执行中的 `blocked` 先进入一次剩余工作窗口，再根据真实成果结束；明确的 `clarify`、权限及用户暂停仍保留原行为。可选应用目录失败只作为上下文缺口，不取消独立工作；界面进度观察者失败不能取消执行。技能准备失败不报告已加载，也不取消通用执行；在新执行中记录缺失的参考上下文，保留原要求，不使用损坏的技能指令或编造未取得模板。初始化阶段未归类故障同样尝试有依据收尾；保存失败仍明确失败，不能声称已持久保存。

MCP 仅在可信适配层确认调用尚未发出时标记 `notExecuted`，允许将失败反馈后继续本地工作；已发送或历史待核对记录始终保持未知结果保护，不能因为新的标记或收尾路径自动重放。文件列表从当前执行回执和归档读取，不重新执行命令。系统登记只证明当前文件存在及版本，不修改原要求、步骤或检查通过状态。

分析与调查没有产物文件时，收尾读取本轮成功的资料和计算回执，允许在同一已选模型上作一次有独立总时限的整理。只接受绑定真实来源 ID 的阶段性分析，不计完整验收；格式无效、来源不存在、上下文不足或整理请求失败时回退真实摘录。收尾请求超时只中止该请求，不能取消任务或丢失摘录。用户视图展示来源名称，完整来源 ID 留在交付记录中。

完整交付的运行时兜底仅在现有全部步骤完成、原要求均通过且证据仍有效、无未知副作用，并通过与正常 finish 相同的文件、HTML、Android、设计和问题检查时成立。不能因交付协议错误将实际已验收任务降成无结果，也不能把自动登记、结构通过或部分要求通过当作完整交付。未通过的视觉、核心实现或行为要求保持未完成，已知问题不被自动关闭。离线测试使用隔离数据与模型／连接器替身，不调用用户公司模型，不改变真实任务，也不操作真实模拟器。

macOS 搜索入口统一为 `/Applications/Ailo.app`。Forge 构建输出放在 `apps/desktop/out/.packages.noindex/`；打包验证和启动探测后、安装同步后自动撤销构建副本的 Launch Services 注册。历史版本目录中的 Ailo 构建自动移入该归档，不删除构建内容，不移动正在运行的构建，不修改用户任务。`node scripts/desktop-discovery.cjs` 可重复执行清理。固定回归关联 `stable-desktop-install`，覆盖归档内容保留、重复清理、运行中保护和 noindex 路径解析。
