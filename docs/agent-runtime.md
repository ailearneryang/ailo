# Ailo Agent 运行链路

本版在统一聊天入口接入项目工作区、意图分流、动态计划、工具执行、暂停恢复和成果面板。此实现是 Ailo 自己的运行循环，不是 ChatGPT 内部实现，也未使用 OpenAI Agents SDK。

## 模型协议与执行

每轮先通过 `route` 区分普通问答与交付委托。问答可以读取材料并回答；交付必须先有计划才可写文件、运行命令，不能以 `reply` 返回代码作为交付。优先使用 Chat Completions 原生 `ailo_action` 工具调用，接收流式参数并在完整返回后校验与执行。只有服务商明确返回不支持工具相关参数时，才切换 JSON mode；明确不支持 JSON mode 时再使用文本兼容模式。鉴权、限流等故障不会当作格式错误重试。格式错误最多自动纠正两次，失败后保存状态并给出用户可理解的提示；不会把多个或未知工具调用中的某一个擅自执行。不能保证任意模型都能稳定遵循协议。

动作包括：route、checkpoint、inspect_source、read_execution、reply、clarify、plan、list_files、read_file、write_file、read_material、read_source、search_materials、read_history、run_command、artifact、finish、blocked、pause。

计划包含目标、已确认决定、验收条件和最多 12 个步骤。单轮最多 48 次模型动作，达到上限暂停，可继续；命令最长 120 秒，模型请求保留分阶段超时。任务状态和每次工具意图/结果独立持久化。停止会中止当前模型请求或命令进程组，已生成文件保留；重启将未结束的运行标为暂停，不自动重放命令。模型恢复时先查看状态和文件。

普通对话仍使用当前模型；没有自动切换到另一个服务商。意图和后续规划依赖模型判断，因此需要真实模型评测。系统不将推理正文或动作 JSON 输出到聊天区。

## 项目与材料隔离

存储位于 Electron userData 下的 `agent/projects/<项目ID哈希>/`：

- `files/`：当前项目代码和成果；项目内不同任务可协作修改。
- `materials/`、`materials.json`：已解析材料及目录。
- `originals/`：新上传的原始文件。
- `runs/<任务ID哈希>.json`：任务计划、决定、工具记录和成果登记。

导入原件先暂存于 `agent/imports/`，首次用于项目时移入该项目。其他项目不能用原件 ID 读取它；跨项目复用需要重新添加。未发送附件的暂存原件目前不会自动清理。

文件工具拒绝绝对路径、目录穿越、符号链接和硬链接。材料与成果读取要求属于当前项目/任务，执行器不接受模型指定另一个项目根目录。原文件、任务状态与模型凭据不在命令工作区内。

命令运行使用 macOS `sandbox-exec` 默认拒绝策略。只开放当前工作区写入、系统程序/库及本机 Android SDK 读取，允许出站网络供下载依赖，不继承父进程凭据环境。HOME、TMPDIR、Gradle 缓存置于项目 `.runtime/`。系统根目录仅允许读取目录本身供动态加载器启动，不递归开放。沙箱不可用时不回退为普通 shell。当前仅支持 macOS；这不等于容器级或虚拟机级隔离，系统工具可读路径和网络权限需要持续审计。

## 上下文

任务模型输入包括原始需求、近期最多 10 条对话、材料目录、计划与决定、有限的最近执行记录和观察。材料全文不再逐次拼入请求。超过预算时移除较早观察和消息，保留最新输入；旧对话可通过 read_history 分段查回。原始消息和文件不删除。

材料通过关键词搜索和定量分段读取；新上传原件支持完整文本/DOCX正文及压缩包目录与指定文本条目。旧材料只有原先保存的解析结果，未保存的原件需重新添加。没有实现语义向量检索或 OCR，也没有 DOCX 内嵌图片解析。独立图片已有多模态消息链路，但依赖所选模型支持视觉，不代表已核对设计画面。文字 PDF 与 XLSX 解析、成果预览和项目记忆见 document-workflow.md。

上下文圆环显示基础输入估算，另列当前会话材料正文大小；它不是实际每次模型请求 token 数。运行时额外计入工具观察并限制请求预算。历史摘要旧字段保留以兼容旧版记录，新的 Agent 路径以结构化任务状态与按需查回历史为主。

## 成果与完成条件

成果必须是当前项目中真实存在的普通文件，登记路径、大小和 SHA-256。完成至少要求有登记成果、成功命令事件、验证发生于当前文件修订后、登记内容未被修改。运行时验证这些客观条件；业务验收覆盖是否充分仍由模型判断，成功退出码本身不能证明 Android 应用功能正确。

界面提供计划、决定、验收条件、最近执行日志、文件夹入口、文字和图片成果预览。HTML 提供隔离静态预览，脚本不执行；JavaScript 默认作为文本显示，APK 在文件夹查看。原生 Android 模拟器交互预览未专门集成。

本机检测到 Java 11，默认 Android SDK 目录不存在。因此本次没有构建真实天气 APK。已使用配置的百炼-GLM-5.2 完成真实最小问候与隔离文件交付测试（生成 hello 文件、执行检查、登记成果），这不代表完成天气应用的端到端验收。用户实际执行 Android 任务仍需要 Android SDK/JDK/依赖，以及必要的厂商 SDK。缺少环境应返回 blocked，不能冒充已经交付。

## 本次交互修正与 ChatGPT 的比较

任务卡不再固定出现“打开项目文件夹”；只有已有成果时，才在“本地成果文件”折叠区提供 Finder 入口。项目已经建立，无需打开本地目录才能执行。中断只提供一个重试/继续入口；对尚未回复的用户消息，重试原消息，不新增“继续”消息。

ChatGPT 官方 Projects 文档介绍的是项目内组织聊天、资料和指令，并没有将打开本地文件夹列为开始工作的步骤。OpenAI API 官方文档公开了 function calling：模型返回工具调用，应用执行并回传结果。Ailo 参考这两项公开机制，但不能据此声称与 ChatGPT 的内部编排、模型能力或故障恢复实现一致。

## 0.1.2 路径兼容修复

查看目录支持省略 path、空字符串、`.`、`./`，并规范化 `./src/` 等相对路径。规范化前先拒绝绝对路径与所有 `..` 分段，再检查符号链接和硬链接，不能通过路径规范化绕过项目隔离。文件读写仍要求具体文件路径。工具失败记录补充 path，便于查明真实模型参数；不保存写入正文或密钥。


## 0.1.3 材料恢复与上下文管理

材料目录按同名原文件的 SHA-256 合并重复导入，保留不同原件版本。旧的仅解析文本记录只在名称、解析文本一致且原件版本唯一时关联原件，旧 ID 保留为项目内别名。无法唯一匹配时不猜测。迁移只在当前项目运行时执行，不修改其他项目。

每次工具调用保留参数与结果配对，任务 JSON 保存尚未压缩的观察结果、已读范围和工作摘要，重启后恢复。累计六次材料读取或接近上下文预算时，要求模型提交累计 checkpoint，之后才移除旧观察结果。原始工具结果与摘要保存在当前任务 `.json.jsonl` 归档，可通过 read_execution 按需回查。摘要由模型生成，仍可能遗漏，读取凭据不能视为需求已经理解。正文过大时按模型预算缩小展示片段，next 对应实际展示边界，完整结果不丢弃。

模型重复 route 同一意图可恢复，不允许通过再次路由改变本轮权限。同一动作第三次重复时暂停；相同失败也独立计数，不会因其他读取成功而归零。初步读取八次仍没有计划时，要求建立可调整计划、澄清关键缺口或说明阻塞。不同读取范围不会被当作重复动作。

大型 JSON 可通过 inspect_source 获取有限结构概览，再以 JSON Pointer 读取局部页面或组件，支持压缩包内条目。此能力不包含图片理解。执行面板增加材料名称、条目路径和读取位置。

验证覆盖旧附件迁移、不同原件版本、旧 ID 兼容、项目隔离、摘要与中断恢复、循环检测、大型 JSON 局部读取和输出预算。真实天气项目数据副本由 14 条记录合并为 7 条，七份原件可读且全部旧 ID 可解析；未在原项目自动重启开发任务。

原生工具调用显式关闭 parallel_tool_calls，并按当前阶段缩小动作枚举。服务商明确不支持并行开关时，仅移除该开关，继续保留原生工具通道。历史动作/结果按时间排序，最新任务状态与阶段要求放在请求末尾。

本次验证结果：68 项自动测试通过；0.1.3 桌面构建成功。配置的百炼 GLM 模型在两份合成材料上完成读取、checkpoint、计划、写文件、命令检查和成果登记。测试不代表完整 Android 天气应用已构建，也不代表所有模型都能稳定遵循工具协议。

## 0.1.4 输出额度与截断恢复

模型设置新增 `maxOutputTokens`（单次最大输出额度），独立于 `contextWindow`。用户按服务商限制填写；保存时校验整数范围及与上下文容量的关系，服务商实际能力仍以接口为准。既有配置不自动扩大额度：Agent 未配置时上限仍为 8192。

Agent 首次请求最多 8192，遇到 `finish_reason=length` 后最多重试两次，额度依次尝试 16384、32768，始终取配置上限与剩余上下文中的较小值。即使额度无法再提高，也要求重新生成更小的完整动作。不会拼接或执行被截断的工具参数；写入大文件时提示拆分模块，不宣称提供了通用文件补丁工具。其他接口故障不作为输出截断重试。

输出截断事件记录请求额度、结束原因、服务商提供的输入/输出及推理 token 统计，以及正文/工具参数字符数，不记录推理正文。旧版“生成的文件内容过长”误报改为准确的模型输出上限提示。设置的输出上限也约束普通聊天和摘要请求。

## 0.1.5 最近请求的上下文统计

Agent 在最终请求消息与工具定义组装完成后计算输入估算，经运行状态推送到界面并持久保存。统计包含系统与扩展指令、任务状态、累计需求摘要、材料目录及读取进度、对话、工具调用与结果、实际使用的工具定义。数值仍采用本地字符估算法和协议开销估算，不等同于模型分词器或账单计量。

面板显示最近请求的时间、模型、状态、输入估算和本次输出额度上限。服务商返回 input/output/reasoning 用量时单独展示，推理不再次累加进输出。重试及接口格式降级创建新的请求统计，不携带之前请求的服务商用量。未收到统计时明确标注，不拿估算冒充实际值。未发送草稿不计入最近请求；没有请求统计的旧任务仍显示“基础输入估算”。容量分母来自当次请求的模型配置，并非服务商能力验证。

## 0.1.6 右侧产物栏

当前任务的已登记成果集中在右侧产物栏，顶部入口可打开或收起，栏内可展开宽度。支持空状态、成果名称/路径/大小、文本和图片预览以及 Finder 定位；二进制和超限预览沿用现有受限预览接口。聊天中的任务卡保留计划与执行记录，以及跳转产物栏的入口，避免重复展示。

产物与材料面板互斥；切换任务时清空选中项及预览，异步预览返回时检查组件是否仍有效，防止旧任务内容覆盖新任务。产物变更时依据文件哈希刷新预览。小窗口中显示可收起的右侧抽屉。产物栏展示 Agent 已登记的交付成果，并非整个项目文件浏览器。

### 0.1.7：压缩包内路径恢复

读取原附件条目前先检查压缩包目录。允许省略唯一匹配的目录前缀，支持目录中的 `./` 前缀；同名条目不唯一时返回候选路径，不猜测文件。`read_source` 和 `inspect_source` 返回实际条目路径供后续读取使用。路径不存在与压缩包读取失败分别反馈，提示模型修正参数，保留现有连续失败保护和项目隔离。

验证：76 项回归测试通过；使用出错项目原附件只读复现，`extractSvg-3-43379.json` 自动解析为 `mcp-materials/extractSvg-3-43379.json` 并成功读取。不修改当前任务或附件。

### 0.1.10：恢复执行与进度核对

已有计划的任务恢复后，route 确认 task 时进入 running，不再一直停在 understanding。每 6 次成功工具操作强制 plan_update，模型须按实际结果核对步骤状态后才可继续执行；允许澄清、暂停或报告阻塞。计数持久化，checkpoint 不清零，旧任务从最近计划后的执行记录恢复计数。状态不按文件写入自动推断；提示要求步骤切换、验收和阻塞时及时更新。计划事件保存步骤快照供回溯。

验证：78 项回归通过，覆盖恢复状态、核对门禁、发布步骤更新、checkpoint 保留计数及旧任务迁移。

### 0.1.11：计划校验可纠正反馈

修复步骤标题超出 200 字符时仅返回“计划步骤无效”、模型无法定位字段而连续重试失败的问题。plan.cjs 统一工具 schema 与运行时长度、数量和状态约束，错误标明步骤索引、字段、实际长度和限制，要求仅纠正问题字段、保留实际状态后重提完整计划。无效计划不覆盖旧计划，不静默截断标题，不自动猜测完成状态。提示要求简短步骤标题，详细进展放任务摘要。

验证：80 项回归通过，包含 229 字符标题拒绝→字段反馈→纠正成功、旧状态保留、边界长度、重复 ID 和错误状态。

### 0.1.12：项目文件与交付成果

产物栏默认列出当前项目实际源代码和文档，支持预览、刷新及打开文件夹，另设交付成果页显示当前任务显式登记的 artifact。文件存在不表示完成或验收通过。列表随任务 updatedAt 更新，旧项目无需重新生成；命令写入的文件同样可见。读取和预览仍限定任务所属项目，拒绝路径穿越及符号/硬链接，隐藏目录、依赖与构建缓存不列出；最多500文件/3000目录条目，截断时提示打开文件夹。

验证：路径隔离回归、打包后界面流程（两类预览、任务切换、重启、小窗口）通过；现有天气项目只读扫描得到51个文件，其中29个 Kotlin 文件。

### 0.1.14：执行中的待发送队列

执行时输入框保持可用，发送文字加入按任务隔离的本机待发送队列。支持逐条编辑、删除、立即执行；立即执行通过既有 steering 通道插入下一次决策，不启动并发执行器。普通排队消息在本轮结束后依次处理，出错、等待澄清、阻塞或手动停止时保留队列。执行中的消息不能编辑/删除。自动发送使用稳定消息 ID 防止保存后重复插入。

验证：构建及隔离 Electron 界面测试覆盖执行中输入、多条排队、编辑、删除、立即插入、自动续发和既有任务/产物流程。

### 0.1.16：多会话调度

默认最多3个会话并发，超出上限进入等待队列；同项目会话按项目串行，避免生成文件互相覆盖。排队不启动模型超时计时，可单独取消；可运行项目按入队顺序获得空位。每个会话的请求、流式内容、运行状态独立管理，执行中允许新建/切换对话，侧栏标示执行或排队。输入草稿随切换保留。会话更新改为存储层串行原子 patch，配置保存保留最新会话数据，补充消息亦走同一保存通道。

验证：84项回归；五会话 Electron 测试覆盖3路并发、排队、同项目串行、单独取消排队、独立回复、新会话及草稿恢复。运行任务仍依赖当前应用进程；退出不会在后台继续。

### 0.1.17：输入框单一动作按钮

移除独立“加入队列”文字按钮。当前会话执行中、输入为空时显示停止方块；有非空输入时同一位置显示发送箭头，将消息加入待发送队列；发送清空后恢复停止方块。保留可访问名称与悬停提示，非执行状态保持普通发送行为。

### 0.1.18：工具流元数据与参数超限恢复

## 0.1.29：Android 标准构建与本机验证

新增 `build_android` 和 `android_device`，均需 task 路由及已制定计划。普通聊天不能调用。

- `build_android` 接收至多 8 个 Gradle 任务名；拒绝 shell、选项和任意工作目录。默认 assembleDebug、testDebugUnitTest、lintDebug。首次以原生弹窗授权本项目；授权仅保存在当前应用进程。文件隔离不变，JDK/SDK 自动发现，HOME/TMPDIR/GRADLE_USER_HOME 为项目独立目录。最长 20 分钟，实时报告 Gradle 状态，可通过原停止按钮取消，取消后不自动重放。一个项目同时只允许一个构建。
- 构建模式允许 Gradle 所需的 bind/listen。实测当前 macOS Seatbelt 的 localhost 选择器仍允许通配地址监听，不能宣称严格仅回环可达。因此它是独立授权的能力，不用于普通 run_command。授权弹窗准确说明网络服务权限。要实现强网络命名空间隔离，应另接 VM/容器执行器。
- `android_device` 支持 status/start/install/launch/logs/screenshot/stop。主进程托管受信任 SDK 工具，不接收任意 shell、设备序列号或模拟器 flags。按项目创建专用 AVD、独立 ADB 端口、独立 HOME；ADB 使用 one-device 排除真实 USB 设备，不接管个人模拟器。首次原生授权后本次应用会话复用。APK 必须是当前项目相对路径；复制到 broker 私有目录再解析包名并安装，不提供卸载/清数据操作。退出 Ailo 时停止管理的模拟器和 ADB。
- SDK 使用 ANDROID_HOME/ANDROID_SDK_ROOT、用户默认 SDK、Homebrew SDK 候选；优先 JDK 17。必须已安装 emulator、cmdline-tools/latest、build-tools 与匹配架构的系统镜像。工具不自动安装 SDK 或接受许可证；缺失时返回明确阻塞。
- 截图保存为 `verification/screenshot-*.png`，可登记 artifact 在右侧预览。截图保存不等于模型已看图；当前动作协议仍是文本结果，不声称视觉验收已完成。
- 成功的 build_android 事件可作为 finish 的构建证据，仍要求修订号一致、计划完成及成果哈希有效。安装、启动和日志结果分别保留，不能用安装成功替代完整验收。

验证：macOS 构建沙箱内完成真实天气工程 Gradle assembleDebug；专用模拟器完成创建、启动、APK 安装、应用启动、日志、截图、停止。68 项运行时/代理/协议/会话回归测试通过。网络规则已实测其限制，不声称完全隔离其他本机网络服务。

### 连续执行批次（0.1.30）

任务默认每 48 个决策循环保存批次进度并自动继续，不返回聊天结束消息，也不重新 route、清空观察结果或重置重复动作/失败计数。用户停止、澄清、权限等待、模型主动暂停/阻塞和完成仍立即结束当前运行。批次保存事件为 `batch_continue`，日志显示中文说明。

每次用户启动/继续的总预算为 240 个决策循环或 2 小时。时间预算在决策边界和动作执行前检查；不会强杀正在执行的工具，工具自身超时和用户取消仍有效。达到预算保存 `execution_budget`，显示实际轮数或分钟数，并明确任务尚未完成。用户可以手动继续；应用重启不会自动重放未完成命令。

跨批保留本次执行的动作指纹；新的成功工具动作或计划步骤状态变化视为进展。重复动作、仅列目录/回查历史/保存摘要不算新进展。一整批无新进展会暂停，原有连续失败和重复动作保护继续生效。此判定仅是启发式保护，不代表验收通过；总预算仍是兜底。输出 token 自适应策略未在本次调整中修改。

### 自适应输出额度（0.1.31）

Agent 首次输出预算仍从 8,192 开始；收到 `finish_reason=length` 后提高预算，后续动作不再重置。成功响应提供 completion usage 时，按消耗的 125%（向上取整到 1,024）预留余量。学习值保存于当前任务 run，暂停/重启后继续使用；模型身份变化后重新学习，不跨项目共享。凭据不参与持久化。

实际请求额度取学习值、模型最大输出设置、剩余上下文三者最小值；学习值另有 65,536 上限。未配置模型最大输出时仍使用既有 8,192 保守限制，不猜测供应商支持额度。提高 max_tokens 不代表必定消耗全部额度，但可能延长生成时间；原有超时和最多两次自动重试保持有效。

纯思考耗尽额度时提示模型收敛分析并提交下一步；已经输出正文/工具参数时要求缩小动作。截断动作始终不执行。执行记录显示中文原因、原额度、下一次额度，避免只显示 `output_limit`。本次仅调整 Agent 决策请求；独立聊天/历史摘要的输出策略保持原有行为。

### 重复读取纠正与原始 JSON 检索（0.1.32）

材料/文件读取及材料搜索采用独立计数：同一范围前两次允许执行，第三次不执行读取而返回 `repeat_warning`，附已读范围、next 和检索建议；没有实质进展又发出第四次相同请求时暂停。新内容写入或新的计划完成状态允许重新回查。写入相同内容、重复计划状态、仅修改 purpose、保存 checkpoint 均不能反复刷新读取额度。动作失败计数不重置，其他动作和总预算保护仍生效。

`inspect_source` 支持可选 query，在原始 JSON 或指定 pointer 的序列化内容中精确匹配（大小写敏感），每次最多返回8个命中片段与定位 offset；返回 next 可继续搜索。读取命中上下文时使用返回的 pointer 与 offset、不传 query。检索遵守现有项目材料归属校验，不把上传资料当作工程文件；搜索结果不计为整段已读凭据。

暂停和纠正日志包含材料名、entry、pointer、offset；正常 inspect_source 执行记录也保留 pointer。此判断仍是启发式进展检测，不代表任务验收完成。


### 项目目录（0.1.57）

界面继续使用“项目”。新建项目由 Ailo 管理，文件在首次执行时创建于用户数据目录的 `agent/projects/<项目哈希>/files`。选择“打开本地文件夹”后，读写文件、命令工作目录与产物查看直接使用所选目录，不复制原文件；任务记录和导入材料仍由 Ailo 独立保存。相同本地目录重复打开会复用项目。未选择项目也可聊天，产生的文件按会话隔离。

### 模型无关的决策恢复

### 精确原文缓存与跨工具读取恢复

`sourceFragments` 在工具预览之前保存原始文件片段，按项目相对路径、SHA-256 和字符范围合并重叠/相邻页，缓存总计最多 48000 字符。`sourceContext` 每轮最多提供 24000 字符，并明确列出完整性和缺失范围；checkpoint 不删除这些原文，恢复提示不再次截断它们。每轮验证当前文件版本；旧归档不能覆盖新版本缓存。旧任务启动时从最近 32 条文件读取归档恢复原文，不重放工具。

`read_execution` 保持默认 `view=record` 的完整归档兼容行为，增加 `view=result` 直接分页读取结果正文。两种视图独立计数偏移量，结果视图保留原始源码的路径、版本和偏移量。恢复期间若原文已完整呈现，重复更换文件范围、归档 ID 或批量读取也按同一源文件版本识别；未提供的范围和显式记录审计不受该检测阻止。

构建修复上下文最多 24000 字符。关联布局较长时提供多个区域（包括尾部）和精确缺失范围，不再只提供开头数行。checkpoint 的压力判断使用可压缩的工具观察量，不因固定指令、工具结构或精确原文增大而每读几个小文件就要求整理状态。

### Android 屏幕规格与运行截图

`android_device start` 支持 `display:{width,height,density,reference?}`，宽高按像素、density 按 dpi，reference 为项目内原设计 PNG。也可保存项目 `android-display.json`。没有显式配置时从已解析 Sketch 页面中占主导的完整画板推断屏幕尺寸；组件母版不参与选择，画板规格有歧义时要求指定目标。无设计依据时使用有说明的720×1280、320dpi竖屏默认值，不再使用 avdmanager 的320×640隐式默认值。布局生成上下文提供目标像素、dp、方向与来源。

屏幕变更仅重启当前项目自有模拟器并更新白名单硬件参数，保留 AVD 数据，不清除应用。ADB 使用独立服务端口和明确的 emulator 序列号。应用若锁定了不兼容方向，截图会显示不匹配；不能通过放大桌面窗口掩盖该问题。[Android 官方 AVD 配置说明](https://developer.android.com/studio/run/managing-avds)

截图保存 PNG 像素尺寸、实际设备密度、安装 APK 的 SHA-256 和原设计依赖；尺寸不符的截图仍可供模型查看以排错，但不能用于验收。含视觉或模拟器运行要求的 APK 交付需匹配版本的截图，不能复用旧包截图；仅要求构建 APK 的任务不强制启动模拟器。像素尺寸通过不等于视觉还原通过：背景、卡片、字体、内容和底栏仍须对照原设计，无图像能力时保留视觉要求待人工核验。

验证：`node --test scripts/android-display.test.cjs` 覆盖目标选择、旧 AVD 配置迁移、数据保留、独立设备路由、错误视口和过期 APK 证据。另在临时项目实际启动模拟器检查尺寸和方向，不操作当前任务或个人设备。

Android Sketch 实现与视觉限制：Android 任务会收到 `androidDesign` 原稿基准，包含画板 ID、组件展开后的区域坐标、字体、文本与位图引用。通过项目内 `android-design.json` 的 `screens` 将原稿 `boardId`、Android `layout`、原稿渲染 PNG `reference` 与实际运行截图 `screenshot` 绑定。布局尚未写出时仍提供源图层基准。源扫描跳过构建目录并对相同提取树按内容去重，保留受限的唯一原稿依赖。

有视觉要求的 APK 在交付前检查绑定、组件解析、当前 APK 的运行截图及文件哈希；本机图像观察器另将参考与运行截图降采样为 64×36 色块，只有平均色差超过 0.28 且超过 85% 色块的色差大于 0.25 时，才报告大面积外观差异。此检查不依赖公司模型是否接受图片，不向模型服务发送新增图像；通过不构成视觉验收，也无法检出所有布局、字体或交互问题。发现明确差异后重新打开末尾步骤并保留修复缺口，不能以 `outcome=limited` 将缺失实现冒充未核验细节。原稿基准不能在同一请求内通过删除或修改提取数据绕过。无 Sketch 或仅要求构建的任务不增加该检查。

产物存在性验收 `file_exists` 与文本解析分开限制：非空普通文件最多150MB，与成果登记上限一致；使用流式 SHA-256 保存和复查版本，适用于 APK、ZIP 等二进制产物。`text_contains` / `json_valid` 仍最多2MB。存在性仅证明文件及版本，不能替代标准构建、安装运行或设计还原。命令检查仍可作为适当的补充证据，但正常大文件不再因文本限额而必须绕行。验收自动恢复预算耗尽时保留成果、未通过检查与原因，以未完成的 blocked 状态返回，不再作为执行异常抛出。

任务恢复的进展与续跑：`read_execution` 接受同一任务的观察记录 ID、事件 ID 和已知的唯一 ID 前缀，优先读取原始观察；观察文件缺失时可从当前任务事件归档还原结果，不重放原工具。找不到记录时明确提示不能据此推断原操作失败。成功的项目模拟器启动、安装、启动应用、具有来源哈希的截图，以及成功验收，参与恢复进展计数；状态查询、日志翻页、重复命名同一截图和失败操作不计入。恢复阶段保持已提升的输出额度，不被小响应学习策略提前缩减；参数过大的恢复仍以缩小参数为主。用户对已阻塞、暂停或失败任务明确续跑时，给予新的有限失败窗口并保留学到的预算、阶段和缺口，内部批次与普通读取不会重新获得窗口。单步恢复将精确源码限制到16000字符，明确保留缺失范围，用户要求、权限、技能与验收标准保留。
