# Agent 效率改造

目标是减少无效模型生成与串行往返，保留通用观察、权限、恢复和验收机制。未更换主模型，未新增供应商未验证的思考强度参数，也未降低验收标准。

## 无动作恢复

- 默认任务决策在180秒内未开始返回动作参数或正文时，中止该次请求。工具名称/调用 ID 元数据不会解除这个计时器。用户停止依然取消整个任务。
- 纯思考耗尽输出预算、空响应和无动作超时共享分阶段恢复：小动作 → 聚焦上下文 → 单步直出；每次决策最多四次请求（初始一次和三次不同策略恢复），不会两次无动作就暂停。保留用户要求、权限、验收及已授权应用工具；单次写入不超过8000字符、命令不超过2000字符，恢复预算最多32768 token（仍受配置和上下文上限约束），无动作等待分阶段为180/240/300秒。聚焦和直出阶段逐项读取，不使用 batch_read；百炼 GLM-5.2 先降为 low，之后使用已支持的非思考模式，未知网关不添加未验证参数。两次不同且未重复计算的有效操作或证据进展后退出恢复；截图与看同图不算两次。计划/摘要不算实质进展。持续无法生成动作时报告模型服务阻塞并保留成果，不重放已执行工具，也不伪装完成。
- 有实际动作参数但被截断时仍可拆分、适度增加额度，最多重试两次。网络恢复使用独立的传输重试策略；无动作超时不进入网络自动重试。
- 输出预算按阶段学习，使用服务商报告的总输出用量（包含思考），避免反复饿死必须思考的模型；缺失用量不推测。减少无效轮次和选择已支持的低强度，比单纯压缩输出额度更重要。

180秒是执行器默认策略，不表示所有复杂任务应在180秒内完成；计时器在实际动作输出开始后解除，后续仍受流空闲与总请求时限约束。较慢但有价值的思考也可能被暂停，需要真实任务测试误暂停率。不会把提前停止当作成功提效。

## 附带进度，减少专门调用

2026-10-23 更新：附带记忆不再清空最近工具结果；独立 checkpoint 保留最近两条，仍可通过归档回查全部记录。固定检查点间隔从12条观察调整为24条、材料读取从6条调整为12条，上下文压力仍可提前触发。源码读取的版本/范围计数跨续跑保留，无关写入或步骤变化不再清空整个计数。跨文件/归档重复原文检查也适用于普通任务阶段。进度只在事实或状态变化时更新，不要求每次动作重写记忆。

任意正常动作可包含：

```json
{
  "action": "read_file",
  "path": "source.py",
  "progress": {
    "steps": [{"id": "implement", "status": "running"}],
    "memory": "累计需求、原始记录来源、已确认事实、未解决问题与下一步，至少20字。"
  }
}
```

steps/memory 可以单独提供。steps 可只提供有变化的已有 ID，按 ID 合并，未提及步骤与原顺序保留；改变计划结构和验收要求仍使用 plan。需要 plan_update 时，下一动作可附带 steps；需要 checkpoint 时，可附带 memory。兼容原有独立 plan/checkpoint 动作。

运行时先验证整个附带对象，再提交进度。附带内容描述执行前的真实状态，不承诺同一动作必然成功；工具失败仍记录错误，finish 仍核验当前版本的成果与证据。计划和记忆更新不能改变工具权限。重复检测忽略 progress，避免通过改摘要绕过空转保护。

初始 route 的工具参数只发送该阶段需要的字段，减少无关工具描述的输入开销。

## 批量只读

batch_read 支持1–6项、最多3项并发，仅限 read_file/read_material/read_source/inspect_source/search_materials/list_files/read_execution。禁止写文件、命令、应用连接和嵌套批量。整个批次先校验，再执行；模型返回多个独立只读调用时可确定性转换，包含写操作或其他不允许动作则整体拒绝。

每项保留稳定 itemId、独立错误和完整归档 observationId。摘要按项分配空间，防止第一项挤掉后续项；长内容通过 next 或 observationId 回查。批量读取与普通读取共享版本/范围重复检测；成功项不随失败项重放。模型仍须根据结果决定依赖它们的下一步。

固定回归测试读取相同六个本地文件：逐项方式需要9次模型决策，批量方式需要4次，读取覆盖一致。这是确定性框架测试，不代表真实任务耗时或质量的提升比例。

## 测量与展示

2026-10-23 更新：除全局最近200条外，脱敏请求诊断按任务保存最近2000条，最多保留最近使用的50个任务；超过范围按最旧任务清理对应诊断文件，不删除任务或产物。字段沿用白名单，不保存提示词、推理正文、工具参数、密钥。累计统计另保存在 run.performance。新增首次动作输出前耗时（仅统计有有效时间戳的请求）、运行时动作错误和验收失败次数，不能把模型请求成功等同于验收通过。进度面板分开展示步骤与验收/视觉验收数量。

运行记录持久化 performance，进度详情新增“执行效率”：

- 模型请求次数、失败次数与累计耗时；传输内部重试按真实请求计数，不与逻辑决策重复计算。
- 可识别的路由、计划、摘要、验收与交付请求耗时；无动作请求次数和耗时。这些是模型总耗时的分类/子集，不能与模型总量相加。
- 工具执行累计时间、工具调用数、批量项数、附带更新次数。批量时间按整体墙钟计，不累加并发项的重叠时间；包括批量归档等运行开销。
- 服务商完整报告用量的请求数、已报告输入/输出/推理 token。缺失的用量不估算，不声称这是完整成本。
- 同一执行暂停后继续会累计；新一轮终结后的用户任务另起统计。model-requests.json 的受控字段增加实际动作类别、首次动作时间、输出诊断和真实 token 数，不记录提示词、推理正文、工具参数或密钥。

本轮加入真实 GLM-5.3-flash 的跨任务对照，原始记录保存在 .local/evals/iteration-20261020。只有完成且通过独立检查、人工验收的试验才能用于正确交付耗时比较；不能据代码改动宣称达到此前讨论的30–40分钟目标。应以相同输入、相同模型/端点、多次运行的最终质量、错误完成率、耗时和真实用量评估；同时统计因无动作预算暂停而未完成的任务。

## 2026-10-23：减少重复决策与受控组合操作

- 完整且不超过8000字符、包装不超过12000字符的显式工具读取，在普通及恢复上下文中保留全文与真实 next；不再将已读完的3525字符日志裁成1028/748字符并要求额外分页。超限内容仍按实际可见范围分页，不把截断内容当全文。
- 恢复进展按证据身份去重，最近512条跨恢复与续跑保留。同一截图及 view_image 只算一次观察，重命名或重复提交不能清零失败预算。新源码修改和有效验收仍可推进恢复；明确续跑仍获得有限尝试窗口，保留原任务和证据。
- 标准构建返回与 Gradle 任务、变体匹配的 buildArtifacts/scopes 和 APK 哈希。输入文件修改/新增使证据失效；构建期间输入变化须重建。扫描覆盖不完整时采用保守版本检查，不虚报完整依赖。项目 verification 目录是设备检查输出，不作为构建输入；运行截图不会反过来使成功构建证据失效。
- android_device(operation="check",path="当前APK") 顺序执行 start/install/launch/logs/screenshot，逐步授权、归档并保存进度。日志读取失败可从缺失步骤恢复；未知或已执行但缺少完整回执的安装/启动禁止重放。会话更换后不复用旧设备状态；APK不匹配、启动失败或崩溃阻止通过。此操作不证明业务交互和视觉还原。
- 相同五项设备操作的隔离测试由8次模型决策降至4次，实际操作仍是5项。这是确定性流程测试，不代表真实任务耗时降低50%。
- 当结构化 nextAction 明确是读取或设备操作、且没有当前 blocker 时，已支持的服务商使用 low 思考；复杂实现、视觉核对、验收和故障分析仍保留原强度。未知公司网关不注入新参数，不换模型。

本轮不自动修正旧任务错误的要求范围，也不自动降低验收标准。真实提效仍须在相同模型、任务和验收口径下验证；源码与离线回归通过不代表正在运行的旧安装包已更新。

## 本轮新增：连续状态、局部编辑和分阶段推理

progress 额外支持 executionState 和 issues，仍随正常动作提交：

```json
{"executionState":{"goal":"修复报告","facts":[{"text":"已确认金额计算有误","sourceIds":["真实事件或观察ID"]}],"gaps":["尚未核对修正后的金额"],"nextAction":"edit_file","expectedResult":"得到修改后的文件版本"}}
```

facts 绑定真实来源 ID；未知内容保留为 gaps。暂停、无动作终止及工具错误保存具体 blocker，继续时与旧成果、归档和下一步一起交给模型。恢复减少无关工具，保留现有权限边界，不引入另一个审核模型。

edit_file 使用 read_file 返回的 SHA-256 version，及 edits:[{oldText,newText}]。每个原片段在原版本中必须唯一，全部片段不得重叠；任何冲突均不修改。单文件进程内串行、提交前再次核对哈希，临时文件 rename 原子发布并保留原备份。外部程序不参与该锁，提交前复核与 rename 之间仍存在极短的并发窗口，不宣称是跨进程文件事务。

官方智谱 GLM-5.3 系列在 route、checkpoint/plan_update 等状态调度决策使用 low；普通实现/设计/修复保持界面选定的强度；小动作恢复使用 low。未知供应商不注入专用参数。此策略须用任务成功率验证，不能用减少思考本身证明收益。

run_command 使用 bash -o pipefail，单独返回 stdout/stderr、exitCode、timedOut、fileChanges。文件扫描最多2000项/64MB，超出或存在未扫描依赖（如 node_modules）时明确标记 bounded 并保留保守版本失效。完整扫描的命令证据记录文件哈希与文件集合；新增、删除或改写依赖后重新验证。只读命令成功且文件不变时不提高项目版本；中断前先提高版本，避免旧记录误用中断前的证据。检查通过仅证明对应程序检查，不证明全部用户语义。

## 跨任务对照

scripts/agent-eval-cases.cjs 固定网页、文档、数据、代码、陌生文件五类，每类正常/修复两个任务，每版各三次，共60次。baseline 在修改前保存全部源码和 SHA-256 清单；候选版冻结单独源码目录。真实请求复用 createChat、传输、工具、观察和验收，无脚本代替模型决策。凭据仅在 Electron 主进程内解密，不写入轨迹，不修改实际用户会话。

```sh
env -u ELECTRON_RUN_AS_NODE <electron> scripts/agent-live-eval.cjs baseline 3
env -u ELECTRON_RUN_AS_NODE <electron> scripts/agent-live-eval.cjs candidate 3
# 对已完成试验统一独立检查，并生成真实截图/打印结果：
env -u ELECTRON_RUN_AS_NODE <electron> scripts/agent-eval-grade.cjs
node scripts/agent-eval-report.cjs
```

每次试验保留结果、请求用量、工作区、固定人工 rubric；独立检查覆盖网页实际点击、文档真实打印分页与裁剪、计算、代码边界和 CSV 无损读回。人工验收 pending 不等于通过；暂停、异常、超时不算成功。费用先报告服务商 token，不推算单价。供应商负载与生成随机性未控制，样本也较小，不能将时间差全部归因于框架。

模型服务返回明确额度/鉴权/服务故障时，评测器停止后续队列，报告单列受阻样本；无动作暂停仍计为框架失败，不能排除。额度恢复后使用同一冻结源码执行 candidate 3 --retry-service；已有成功试验跳过，受阻试验先整体归档到 service-blocked，再从相同固定输入重新开始，保留全部历史成本。--preflight 只校验配置和凭据，不调用模型。评测 Electron 使用独立 userData，凭据从真实配置只读解析。

本轮完整基线30次，前一冻结候选6次完成并通过独立检查，其余24次被 HTTP 429 阻断（均保存在 candidate-attempt3）；随后一次小型健康检查仍返回429/1113，响应提示额度相关。尚未完成完整模型对照和人工验收，不据此给出整体提速或成本改善比例。该状态详见 .local/evals/iteration-20261020/report.md。

最后离线复核补充了“同图多次裁剪始终以原图坐标映射”的修复，新增回归验证。为不混用源码版本，前一候选6次通过记录作为诊断保留；最终源码重新冻结在 candidate-source。额度恢复后运行 candidate 3 完成最终30次模型对照，而不是把旧样本直接算入最后版本。

设备组合核对的收尾保护：子操作在独立事件及结果归档成功后参与恢复进展，复用旧步骤不会再次清空失败累计。复用安装、启动前须核对模拟器会话及已安装 APK 哈希；其他设备操作进行中或同任务存在结果未知的设备副作用时，不返回缓存检查。再次核对已完成流程时，仅复用已确认的安装和启动，重新读取日志、截图以反映当前状态。无效、空或超过150MB的 APK 在设备授权和启动前拒绝。以上由隔离回归覆盖，没有操作用户的真实模拟器。

收尾回归另覆盖两个相邻问题：已确定失败的只读操作不会阻止更换检查参数，缺失回执仍阻止重放；用户上传图片的传递独立于本机截图观察服务。关闭图像输入仍不发送图片，端点明确拒绝后，本次执行后续决策也不再重复发送图片，不会因此把视觉验收标成通过。
