# 0.1.65 长任务优化

本轮保持用户配置的 GLM-5.2、服务端点及原任务验收标准。源码改造、离线故障回归、宿主验证、真实任务质量分别记录；不能据代码或离线测试宣称已经达到一小时或提高了真实完成率。

## 动作与构建

- `action-identity.cjs` 为重复动作与错误建立一致身份，去除 purpose/progress 等展示记账字段，使用相关文件、资源及构建输入版本。相同字节的 write_file 返回 `changed:false`，不覆盖、备份或提升项目版本。
- 构建身份覆盖 Gradle tasks、完整源码清单、SDK/JDK、隔离 Gradle 配置与构建运行时代码。缓存位于工程命令不可写的项目元数据目录；仅完整输入、环境及产物 hash 均一致时复用成功结果。缺少完整扫描、动态依赖和未知结果不复用。
- 构建不再无条件增加源码 revision；实际源码修改、中断的写操作仍保留保守失效。复用构建和 no-op 写入不计真实进展，不因此重置恢复预算。

## 恢复与验收

- 持久化 FailureEpisode，以实际目标、错误类别及失败要求归因。已解决的独立问题不占用后续问题的恢复机会；摘要、checkpoint、无关读取和更改步骤名字不能重置同一问题。
- 同一错误有有限策略窗口，跨片段保留。明确用户续跑只增加有限机会，不清旧证据；自动分段不赠送新的无动作预算。
- 循环恢复先复用凭据、再聚焦修复。持续相同决策或重复已经通过的验收，提前准确阻断而非耗尽整个任务的数百轮。重复验收的说明或事件别名不构成新证据。
- 请求格式错误、待核验证据、确认产品差异分别处理。同一截图可以补齐 pending 的核验；确认 mismatch 仍要求真实修复，不能通过修改说明或重新截图洗掉。
- requirements 的用户语义、类型与 scope 不放宽。独立 evidenceBinding 只能指向明确已存在、匹配类型的证据；纠正绑定会撤销旧 pass，仍须通过原验收的新鲜度与覆盖范围检查。旧任务的错误 scope 不自动迁移。

## 模型请求与上下文

- 正常阶段使用短核心提示词及当前工具说明，保留原 AGENT_PROMPT 导出兼容已有集成。恢复核心压缩至约 1,556 字符；选定技能仍保留。工具菜单是推理辅助，不是新增权限；完整允许动作目录可见，最多两次受控发现。
- 最终 wire messages 与实际 schema 一起计算输入、生成额度和保护余量；具名工具、JSON 与文本回退均重新计算。超窗请求在发送前明确拒绝。
- 正文不会解除无动作期限；工具参数开始后有独立、有界的完成期限。取消仍终止全部请求，传输重试保留原错误分类。
- taskState 独立保存原始用户要求与更正，不由工作摘要覆盖。模型输入中的长条目或旧条目遗漏明确标注，可通过原历史回查；不会声称截断内容完整。
- 端点仍遵循已确认能力，不向未知公司网关盲传参数。实际发送的思考控制、工具流、阶段、预算与发现次数进入脱敏诊断。

## 持续执行与可观测性

- 默认每片段最多 120 次决策或 30 分钟；同一次任务最多四片段、总计两小时。只有新操作或新读取证据、且没有未知副作用时才自动接续；单纯计划和摘要不能续命。
- 自动片段复用任务、要求、失败账本与浏览器页面，不重新 route。最终结束、真实暂停、权限等待、异常或取消时释放浏览器。未知安装、命令等副作用不重放；历史只读中断不永久阻止续段。
- 每次执行记录进程启动时的运行时／提示词／工具指纹、版本与模型配置指纹；开发模式修改文件后需要重启，已经加载的模块不会自动替换。面板详情展示运行标识、复用与自动接续计数。
- 明确用户续跑、运行时接续和补充指令分别记录来源。旧执行缺少完整跟踪时，人工干预计数为未知，不写零。

## 0.1.66：首次真实实测后的修复

0.1.65 于 2026-10-25 的一次 GLM-5.2 冷启动天气任务耗时 304743 ms，16 次请求，输入 273324、输出 19968 tokens，最终 blocked，未产生正确交付。宿主原集合 414/414 通过不代表这次任务成功。无 baseline，不能计算性能提升。原实验和冻结源码保留。

- Node/npm 在用户 NVM 中已安装，旧隔离命令 PATH 未包含它们。受限发现当前 Node、标准安装与 NVM 的明确版本，仅授权所选二进制目录和 npm 包目录；项目内生成精确路径包装器。隔离 HOME、npm 配置、缓存与安装前缀，不继承个人令牌或 shell 启动脚本。上下文将发现与实际验证分开。
- 天气实测在解密凭据和调用模型前，通过所选源码的真实隔离命令执行 Node/npm 版本检查。缺失或环境拒绝立即停止，不消耗模型尝试诊断工具路径。仍须后续验证 Android、API、功能和视觉。
- JSON 回退消息包含当前工具的参数合同，最终预算包含该合同；batch_read 必填字段明确。计划前读取只提供 memory 更新；不存在的步骤依然拒绝。已有计划优先附带更新，必要时可发现完整 plan。
- 批量原文在当前上下文只保留一次；ID、分页与归档仍可回查。checkpoint 观察压力按模型容量分配（四分之一可用容量，上限120K估算tokens），保留24条观察/12条材料的节奏；累计未整理归档体积另计，旧大历史仍受保护。两次早期 checkpoint 曾花79.9秒，这只说明可减少该类开销，尚不保证总耗时改善。
- JSON 错误只记录偏移、字类、长度、工具片段数等标量，不记录原始参数或可能含敏感内容的解析错误文本。连续纠正仍最多两次。恢复核心提示精简至1394字符并保留权限、原要求、未知副作用、验收和交付规则。
- CLI明确区分试验结束与成功交付，无基线不宣称对照提升。新增故障回归覆盖实际发现；离线通过后仍需正常宿主环境验证与重新实测。

- 自动分段保留同一已选不可变技能包内运行生成的依赖和锁文件，每次仍逐项校验源文件哈希并恢复原始脚本；取消选择时清理整包，拒绝路径符号链接和缺失归属标记。真实分段回归验证依赖只安装一次，篡改的脚本被恢复。此问题是代码复现的续跑隐患，不能冒称0.1.65本次五分钟失败已触发该场景。

归档体积使用启发式估算。旧会话只有预览或缺少估算元数据时可能低估，缺失条数单独标记unknown；不宣称精确恢复全部旧归档token，24条观察/12条材料节奏及真实请求容量保护继续生效。去重仅适用于batch_read，子项缺少明确分页信息时保留父项原文和next/total。
