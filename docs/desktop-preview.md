## 当前能力

- Electron + React 桌面界面，项目选择、可搜索项目浮层、本机账号注册登录。
- 聊天框右下角选择模型，可进入自定义模型设置，支持添加、编辑、移除、默认模型和加密保存 API Key。
- 主进程调用用户配置的 OpenAI 兼容 Chat Completions 接口。API 地址填写接口前缀（例如 `https://example.com/v1`）或完整 `/chat/completions` 地址。
- 支持真实多轮文字对话，保留用户与助手消息、模型名称和文本附件上下文。Enter 发送，Shift + Enter 换行。
- 消息发送前保存到本机，回复后再次保存。调用失败或应用退出留下的未回复消息可重试，不重复追加用户消息。
- 支持停止请求、分阶段超时、网络错误、认证错误、限流/额度提示。不会将服务商原始错误正文或密钥显示到界面。
- 无模型时显示配置引导，不再用固定交付问卷冒充聊天。旧版任务数据保留，原始请求可发送给模型，旧演示答案仍保存在数据中。
- 材料侧栏按需打开。支持 DOCX 正文和表格、文本、Markdown，以及 ZIP、7z、TAR、TAR.GZ/TGZ 压缩包中的 DOCX 和 UTF-8 文本、代码和配置文件。包内文件清单与可读正文一起进入对话上下文，附件显示读取/跳过数量。PDF、图片、嵌套压缩包和依赖目录不解析；RAR、单文件 GZ 暂不支持。
- macOS 使用系统 bsdtar 从标准输出读取压缩内容，不展开压缩包目录或执行包内文件。包内 DOCX 使用私有临时文件解析后立即清理。对话材料不再限制原文件为 20 MB、一次最多 10 个；每包最多 1000 条目、读取 64 个文本文件，文本每个最多 1 MB，DOCX 每个最多 20 MB、正文 XML 最多 4 MB，总正文最多 100000 字符，截断与跳过明确标注。读取有时间和输出容量限制。
- 渲染进程保持隔离，模型请求和凭据解密在主进程执行。仅发送到配置的接口，拒绝自动跟随重定向。

## 边界

目前使用流式回复，正文逐步展示；兼容服务商返回的完整 JSON。不包含工具执行、自动开发、动态任务执行、云端账号同步或自动更新。本机账号不验证邮箱，项目、对话和模型属于当前电脑的共享工作空间。

消息和历史上下文会发送到用户所选模型服务商。密钥使用 Electron safeStorage 加密存储，读取接口只返回是否配置，不将密钥或密文返回界面。密码使用随机盐与 scrypt 哈希。

## 上下文用量与自动整理

输入框模型选择器旁的圆环显示当前上下文占比，点击打开用量明细。包含草稿、附件、系统提示词、专家与技能和有效历史摘要。当前为混合语言启发式 token 估算（ASCII 字符约 /3，其余码点约 ×1.5，并计消息开销），不用于计费；弹层另列服务商返回的上次正式回复 `usage.prompt_tokens`，不混同于当前估算或累计用量。

在模型设置中填写服务商公布的总上下文容量（4096–2000000 tokens）。未填写的旧配置按 32768 估算，弹层明确提示这是默认值，并非自动识别出的模型上限。预留 15% 输出空间（最少 1024、最多 8192），正式回复通过 `max_tokens` 限制输出长度：初始目标 8192 tokens，续写/重试目标 16384，均受剩余估算上下文容量（另留 128 tokens 余量）约束；弹层预留值为最低规划空间。

发送前达到容量 80% 时，使用当前模型整理较早对话，优先保留最近 4 条消息；空间不足时减少保留条数，但最新消息始终完整保留。较早的大附件按容量分段整理并合并到摘要，摘要保留目标、约束、更正、决定、关键事实与待办；每个请求控制在估算窗口内。最终摘要长度和模型生成额度分开计算：摘要仍以容量的 12%（最多 4096 估算 tokens）为存储上限；生成请求分配更大输出空间，并据此缩小输入片段。遇到服务商 `finish_reason: length` 或完整摘要仍过长时，每个片段最多自动尝试 3 次，逐步增加生成额度（不超过总窗口 55% 或 16384 tokens）、减少片段大小并要求更短摘要。重试始终从原片段和上次有效摘要开始，不采纳截断内容。鉴权、网络等其他错误不触发这类重试。单次最多 64 次整理请求（包含重试），每次请求采用下述分阶段超时，停止按钮中止整个过程。整理会产生额外模型调用，摘要可能损失细节。

摘要成功后单独保存于对话，原始聊天与附件不删除；正式回复失败后仍可复用摘要。摘要指纹不匹配历史时自动失效。弹层支持展开查看摘要。最新消息/附件/扩展本身超限，或摘要失败、无效、过长时明确提示，不静默截断。此机制不能保证所有服务商的真实 token 上限，也不能解决网络或服务商超时；容量需按实际模型设置。

策略参考：[WorkBuddy/CodeBuddy 自动压缩窗口](https://www.workbuddy.ai/docs/cli/release-notes/v2.136.0)、[OpenAI Compaction](https://developers.openai.com/api/docs/guides/compaction)。当前实现为兼容 Chat Completions 的文本摘要，不是 OpenAI Responses 的原生压缩接口，也不声称复刻 ChatGPT 未公开的内部机制。

## 流式回复与分阶段超时

Chat Completions 请求启用 `stream: true`，解析 SSE 事件、跨网络块的 UTF-8/CRLF、`[DONE]` 和 `finish_reason`；兼容服务返回非流式 JSON。正文经受信 IPC 逐步显示。`reasoning_content` / `reasoning` 只更新“模型正在思考”状态和活动时间，不展示、保存或转发思考正文。

首次有效正文/思考内容允许等待 180 秒，之后连续 90 秒没有有效内容才触发空闲超时；单次请求总时长上限 15 分钟。纯心跳不延长等待。摘要与正式回复分别计时，超时提示说明阶段及原因。流中错误、非法 JSON、缺失结束标记的中断不能视为成功回复。

失败或停止后，已收到的正文作为 `partialReply` 保存在对话中，标记“未完成”，可展开查看并在重启后恢复；不会进入正式消息历史或后续模型输入。重试成功后清除该草稿。模型仍持续生成时不再受原先 90 秒总时限打断。

验证：`node --test scripts/chat-stream.test.cjs scripts/chat-service.test.cjs scripts/context.test.mjs scripts/extensions.test.cjs`；`PLAYWRIGHT_MODULE=… node scripts/stream-smoke.cjs` 验证本地 SSE 模型的中途显示、停止、草稿恢复、重试排除草稿。未使用用户真实服务商进行验证。


正式回复遇到 `finish_reason: length` 时最多自动补接 2 次：有正文则携带原请求与累计正文，要求紧接末尾、仅补充剩余内容；无正文则提高生成额度重新请求。每次重新检查输入与输出是否可容纳，空间不足时明确提示；流式界面累积显示全文，成功后只保存一条助手消息。到达重试次数上限仍不完整时保留未完成正文。自动续写依赖模型遵守指令，不保证绝无重复。停止按钮为 34×34，中心图标为 11×11。

## 可点选的澄清卡片

确实需要用户选择时，模型可在文字回复末尾返回 `ailo-questions` JSON 代码块；主进程校验后拆为正文和 `clarification` 数据。每轮 1–3 题，选择题 2–4 个选项、最多一个推荐项，也支持材料题。普通回复无需 JSON 模式或工具调用，格式无效时保留原文字，不猜测生成选项。历史纯文本不会自动改造成卡片，可让模型“把上面的未决问题改成可选卡片”。真实模型遵循格式的效果仍取决于服务商和模型。

推荐项默认预选，每题支持自定义回答；用户明确点击“提交答案”才发送。材料题支持现有文件选择器、移除文件、稍后提供及自定义回答；选择稍后提供或自定义时不会发送已经添加的文件。未解析文件不能作为已读取材料提交。非阻塞默认方案在折叠区展示。

提交产生一条普通用户消息，包含逐题答案和明确选择发送的附件；同时保存问题消息 ID 和答案，重启可查看已提交结果。只允许最近一条助手消息的未提交卡片交互；已提交或已继续其他对话的卡片不再允许重复发送。调用模型失败后按现有消息重试，不重复追加答案。提交卡片不清空输入框里另写的草稿。

原始问题数据会随消息序列化为模型上下文，也计入用量估算和历史摘要。流式阶段不展示未完成的协议 JSON。推荐、选择和已提交状态使用原生单选控件与 fieldset/legend，支持键盘操作。

验证：`node --test scripts/clarification.test.mjs`；`PLAYWRIGHT_MODULE=… node scripts/clarification-smoke.cjs` 用独立数据和本地模拟流式服务验证预选不发送、自定义回答、稍后/附件、提交、失败重试、重启。截图 `.local/clarification-card.png` 与 `.local/clarification-small.png`。

### 本地启动名称（0.1.35）

`npm start` 先构建并打包，再直接启动当前平台的 Ailo 应用，终端仍能看到主进程日志。macOS Dock 因此使用 Ailo.app 的名称和图标。`npm --prefix apps/desktop run start:dev` 保留直接运行 Electron 的调试方式，该方式的 Dock 名称仍可能显示 Electron；app.setName 只改变运行时名称，不能替代原生应用包标识。更新启动配置不会自动关闭正在执行任务的旧进程，请保存/停止任务后退出并重新启动。
